# Slack 普通会话输入与最终答复

## 用户结果

在项目频道发送“查看一下 AWS 昨天的费用”时，Codex 收到这条原话，Slack 正文显示完整的费用答复。“我先核实账号”等过程说明留在原生会话中；“本轮回复”继续展示命令和工具执行进度。最终答复中的多段文字、列表和表格完整保留。

## 原因与调整

Codex 原生消息使用 `agentMessage.phase` 区分 `commentary` 和 `final_answer`。原先实时消费与回合读取都连接全部消息，导致过程说明进入最终正文。现在两条路径共用最终答复选择逻辑，以 `item/completed` 的完整正文为准；无阶段的模型使用最后一条完整消息。缺少完整消息通知时，从原生回合读取结果。

普通回复由 Codrive 持有收件及回复位置，并消费 App Server 事件发送到 Slack。原先附加在每轮用户输入后的项目目录、来源 JSON 和 Skill 操作说明退出普通输入；需要登记工程工作、发送文件或回答待决定问题时，由对应 Skill 按当前原生会话查询已有 Slack 收件记录。项目目录和产品登记继续通过各自的查询命令按需读取。

本次复用已有会话、收件与发送回执，数据格式和持久字段保持原契约。历史消息与回执保留其已发送内容。

## 验证

回归覆盖过程说明排除、完整多段最终答复、命令卡片保留、无阶段模型、缺通知后的原生读取，以及原样用户输入和按会话精确读取来源。运行结果与发布证据记录在本次任务状态文件中。
