# Slack 工作空间识别与频道创建

用户在私信要求为 `pietra-ai-workspace` 创建同名频道时，机器人只读取 Codrive 产品登记，把同目录的 `Pietra Social / Pulse` 当成工作空间；随后创建频道的直接 API 请求因缺权限失败，又退到了锁屏界面。

根因有两个边界：全局私信的状态目录被错误标为仓库路径；本机 Codex 保存的工作空间与 Codrive 产品身份没有分别核实。Slack App Server 的桌面项目工具列表为空，不能依赖桌面会话里的项目查询工具。

本次沿现有模型修复：

- 私信保留中立执行目录，提示词给出准确 `workingDirectory` 和可空项目名称、仓库路径；状态命令显示真实目录与作用范围。
- `codrive-control local-projects` 只读并投影 Codex 现有保存项目的名称和根目录；文件或格式不可用时如实报告。项目识别结合目标目录用途与产品事实；不同身份只共享目录时复用现有空任务登记，不重命名原产品。
- `slack.create_project_channel` 先核实本地项目，再通过 API 创建频道、邀请配置的本人、写入既有绑定。重复已绑定同名频道复用原记录；部分成功保留真实频道 ID 供显式续办，重名不自动接管其他频道。
- 应用模板补充公开频道 `channels:manage` 和私有频道 `groups:write`；已安装应用需要重新授权使权限生效。

本次没有新增持久字段、项目体系或补偿状态机。通过会话上下文、只读项目发现、频道业务流程的回归验证，辅以新上下文身份识别与真实 Slack 授权、创建绑定验收；各项实际结果保存在本次任务状态记录中。
