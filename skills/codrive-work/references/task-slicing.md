# 任务拆分方法

把已确认的产品结果整理成可独立交付和验收的任务。主 Skill 负责目标归属、已有授权、必要产品事实同步、任务写入和交接；本页负责拆分粒度、前置结果和迁移顺序。

## 复用已有决定

先复用当前对话已有资料。用户提供规格路径、议题编号或链接时，读取正文和讨论记录。以当前产品契约、已确认里程碑、规格和已有任务为范围依据，区分确认结果、未决选择和候选增强。任务文档引用已有规格的相关决定，并独立说清本任务的结果与验收；已经明确的事项沿用现有决定。

## 完整行为切片

每项任务贯通完成一个业务结果所必需的层次，并能独立演示或核验。后端任务以接口、处理流程、数据和直接验证形成完整结果；只有当前目标包含界面时才纳入界面工作。按业务结果拆分，避免把表、接口、页面和测试分别变成无法独立验收的任务。

任务大小以独立交付和审查所需的上下文为参考，保持职责完整。只有当前结果确实依赖某项前置重构时，才把该重构安排为前序任务；能直接完成的局部变化保留直接路径。

## 真实前置结果

在任务文档中写明需要哪个任务交付的什么结果，以及缺少它为什么不能开始；可独立推进的任务保持独立。同一模块、排列顺序或可能的文件冲突本身不构成业务前置依赖。展示计划时一并展示这些理由，沿用主 Skill 的已有授权判断。

新任务登记 `title` 和 `taskDocumentPath`。Codrive 任务选择会结合当前代码、任务状态和容量重新判断关系；本页中的依赖是规划依据，实际启动仍由 Codrive 负责。

## 大范围机械迁移

一项机械变更影响大量调用方，导致任何局部修改都无法独立通过验证时，按兼容扩展、分批迁移、移除旧形式的顺序拆分。先让新旧形式共存，再按可验证的影响范围迁移调用方；确认所有调用方完成迁移后移除旧形式。任务之间只标注真实的前置结果。

先确认当前迁移确实需要分批兼容；能在一个可验证任务内完成的机械修改直接完成。每个迁移任务按 Codrive 独立工作、审查和合入的生命周期交付；批次不能独立通过必要验证时，重新划分边界或把相互依赖的改动合为一个可完整验收的任务。外部兼容及旧形式退出条件以既有契约和真实调用方证据为准。

## 任务命名与信息归属

标题直接表达业务动作和对象，让人从看板上看懂交付结果。排序交给看板顺序，任务引用使用业务名称；已有路线图编号放在来源引用中，用户明确指定的任务名保持原样。目标项目已经唯一确定仓库时沿用项目上下文；跨仓库任务在文档中明确各仓库的交付边界。

正文与验收按[任务文档模板](task-document.md)组织。必要的前置结果写在文档中；执行顺序与工作树、审查、合入流程由对应生命周期负责。

## 任务正文与验收

已有任务能完整承载结果时继续使用它，任务状态决定修改或新增路径，按主 Skill 处理。没有文档路径的历史任务继续读取其 `description` 和 `acceptanceCriteria`。

引用决定性资料时给出可查找的路径或链接。代码片段只保留比文字更准确的已确认决定，例如状态转换或数据结构，并简要标明来源；保留表达决定所需的最小部分。
