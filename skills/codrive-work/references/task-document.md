# 任务文档模板

任务文档是交给下一位执行者的需求依据。它说明任务产生的背景、实际要解决的问题、期望结果，以及已确认的做法为什么能解决这个问题。Codrive 的规划、执行与审查每轮读取原路径的当前内容；文档更新后，后续回合按新内容继续。

写文档前，读取当前讨论、项目资料、相关任务和决定性来源，提取与本任务有关的事实、已确认决定及其理由。让接手者能从背景和问题理解目标，再依据已确认的做法处理实施中的细节。

```markdown
# <任务名称：具体动作和对象>

## 背景与现状

<谁在什么场景下做这件事；目前怎样做；哪些已知条件和约束使这项任务产生。>

## 要解决的问题

<当前具体卡在哪里，对用户或业务造成什么影响；说明问题本身及解决它的必要性。>

## 目标结果

<完成后谁能做什么，或系统会出现什么可核实的变化；写明本任务负责的范围。>

## 已确认的做法与理由

<按实际流程说明已确认的关键做法；逐项解释它们怎样回应前述问题，以及选择它们所依据的事实或取舍。留给执行者决定的实现细节说明其约束。>

## 验收场景

- <给定具体前提或输入，执行什么操作，应观察到什么结果；对应前述问题、目标或关键约束。>
```

按任务实际情况补充：

```markdown
## 前置结果

- <依赖哪项任务交付的什么结果，以及缺少它为何不能开始。>

## 依据

- <用可定位到相关章节的链接，或文件路径加段落、行号引用权威规格与已确认决定；说明它约束本任务的哪项做法或验收。>

## 待确定事项

- <现有材料尚不能回答、且会影响结果的具体问题及当前处理状态。>
```

背景、问题、做法和验收围绕同一项任务形成因果关系，篇幅随已确认信息和任务复杂度变化。依据不足的背景或理由标明待核实；会改变业务结果的未决选择按所属 Skill 的授权流程处理。有外部权威来源时，在“依据”中指向适用章节并说明如何核对，完整原始规则仍由该来源维护；没有独立来源时，把当前讨论中已确认且影响本任务的内容写完整。自然语言使用中文；代码标识符、路径和没有通行中文称呼的固定名称保留原文。
